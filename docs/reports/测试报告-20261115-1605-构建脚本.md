# 测试报告：Debug/Release 一键构建脚本

- 日期：2026-11-15 16:05
- 主题：新增 `cmake-debug.bat` 与 `cmake-release.bat`（英文）

## 1. 测试范围

| 文件 | 变更类型 | 是否在测试范围 |
| --- | --- | --- |
| `cmake-debug.bat` | 新增（Debug 配置+构建脚本） | 是 |
| `cmake-release.bat` | 新增（Release 配置+构建脚本） | 是 |

不在本次范围：CMakeLists.txt、全部源码与测试逻辑（零改动）。

### 设计要点

- 复用既有工具链（CMake + MinGW Makefiles 生成器 + mingw32-make），无新增第三方依赖（L 系列合规）
- 单配置生成器下切换同一 `build/` 目录的 `CMAKE_BUILD_TYPE`，产物路径不变，`tests/scripts/run_tests.py` 依赖的 `build\collector.exe` / `build\collector_tests.exe` 不受影响
- 用法：`cmake-debug.bat [jobs]`（默认 4）；每步检查 errorlevel，配置/构建失败即退出并返回非零码
- 结束后构建目录停留在最后一次使用的类型（脚本实测顺序为 Release → Debug，当前为 Debug）

## 2. 测试方法（可复制重放）

```bat
cd /d c:\github\cpp_works\collector
cmake-release.bat          & rem Release 重配置 + 全量重编译
cmake-debug.bat            & rem 切回 Debug
python tests\scripts\run_tests.py --skip-perf
```

环境：Windows + CMake（MinGW Makefiles）+ MinGW GCC 8.1。

## 4. 已知问题

1. 两脚本共用 `build/` 目录，交替执行会触发增量重编译（切换构建类型必然重编全部目标，属 CMake 正常行为）；如需两种类型共存可改为独立 `build-debug/`/`build-release/` 目录，但会破坏 run_tests.py 的固定路径，未采用。
2. 默认并行数 4 为经验值，可通过参数 `cmake-release.bat 8` 调整；未做 CPU 核数自动探测（避免脚本复杂化）。
3. `MinGW Makefiles` 生成器要求 mingw32-make 在 PATH 中（与现有构建方式一致）；未在 PATH 的环境会报 configure 失败并退出。
