## 2. 关键实现决策

### 2.1 文件操作层与 std::filesystem（工具链演变）

**历史背景**：项目初期本机工具链为 MinGW-w64 GCC 8.1.0，其 libstdc++ 存在编译期缺陷（`bits/fs_path.h:237` 中 `path` 比较运算符无法解析，最小程序即可复现），且发行版缺少 `libstdc++fs.a`。因此存储层当时**不使用 `std::filesystem`**，改用 `util.h` 中的轻量文件操作层。

**现状（2026-11-15）**：本机工具链升级为 **MinGW GCC 16.2.0（C:\mingw64）+ CMake 4.5.0**，旧缺陷消除（最小程序 `-std=c++17` 直接编译链接运行实测通过，无需额外链接库）。经人工确认，`std::filesystem` **禁令解除**，并已按确认的**方案 A**完成迁移：`util.cpp` 内部实现改用 `std::filesystem`（全部使用 `std::error_code` 重载，不抛异常，符合 C5/C6），`util.h` 公开 API 与语义保持不变，调用方零改动；Win32/POSIX 平台分支（`GetFileAttributesA/_findfirst/_mkdir/opendir/stat`）全部消除。`path_join` 保留字符串拼接实现，维持 `'/'` 分隔符输出约定（docs/05）。

迁移前基线（历史实现，行为语义已被等价保持）：

- `file_exists`（Windows 用 `GetFileAttributesA`，POSIX 用 `stat`）
- `make_dirs`（逐级 `_mkdir`/`mkdir`）
- `rename_replace`（`rename()` 在 MSVCRT/POSIX 上均为替换式，失败时回退删除后重命名；该兜底逻辑在迁移后保留）
- `list_csv_files`（Windows `_findfirst`，POSIX `opendir`）

语言层面仍全面使用 C++17（`std::optional`、`std::shared_mutex`、结构化绑定、`if` 初始化语句等）。

### 2.2 依赖库版本适配

- nlohmann/json 实际版本为 **3.1.2**（低于 3.3），无 `json::contains()`，代码统一使用 `find(key) != end()`（`api.cpp` 中封装为 `json_has()`）。
- cpp-httplib 0.66.0 要求 `_WIN32_WINNT >= 0x0A00`，CMake 中全局定义 `-D_WIN32_WINNT=0x0A00 -DNOMINMAX -DWIN32_LEAN_AND_MEAN`，并链接 `ws2_32`。

### 2.3 白名单中间件挂接点

使用 `httplib::Server::set_pre_routing_handler`，在路由分发**之前**执行，命中拒绝时返回 `HandlerResponse::Handled` 短路整个请求（含静态页面），未命中规则时返回 `Unhandled` 放行。来源取 `req.remote_addr`（TCP 层，不可伪造），不解析 `X-Forwarded-For` 防伪造绕过。

### 2.4 error_handler 覆盖问题

httplib 0.66 对**所有** `status >= 400` 的响应都会回调 `set_error_handler` 注册的 handler。若业务 handler 已写入统一错误体，必须跳过，否则业务错误码/消息会被覆盖。`api.cpp` 中的 error handler 以 `res.body.empty()` 为判断条件，仅对无路由匹配的 404/405 等生成兜底 JSON。

### 2.5 存储一致性

- 锁：`file → std::shared_mutex` 映射（映射表由 `std::mutex` 保护）；读 `shared_lock`，写 `unique_lock`。
- 落盘：写临时文件 `<name>.csv.tmp` → `rename_replace` 原子替换；失败删除临时文件并返回 500，旧文件完好。
- 批量写：单锁内全量校验 → 内存修改 → 一次落盘；任一条目非法则整批拒绝（不落盘）。
- 无读缓存：每次请求从磁盘加载，外部工具（如 Excel）修改文件后立即生效。

### 2.6 CSV 编码

UTF-8 带 BOM（`EF BB BF`）+ 标准表头；字段含 `,` `"` 或换行时按 RFC 4180 加引号并转义 `"`。读取由 rapidcsv 完成（自动剥离 BOM、处理引号字段）。

### 2.7 日志系统（spdlog 封装，2026-11-15 升级）

原 `util::log_line`（printf + fflush）自 2026-11-15 起替换为 `common/logger`（封装 `third_party/spdlog` 1.17.0，编译库形态 `spdlog_lib`，bundled fmt 随附）：

- **初始化/停止**：`init_logger(LogConfig)`（可失败，统一出口；重复调用拒绝）→ `shutdown_logger()`（flush + 异步线程池排空，幂等 noexcept，退出顺序最后一步）。
- **配置**：app.toml `[log]` 段（`level/async/queue_size/file_path/max_file_mb/max_files/console`），键缺省用 `LogConfig` 内置默认（info/true/8192/logs/tagledger.log/10/100/true）；非法类型 WARN 忽略。
- **保留策略**：`rotating_file_sink`，单文件 10MB 轮转、含当前文件最多保留 100 个（spdlog `max_files` 计轮转旧文件数，实现传 `max_files - 1` 对齐总量语义）。
- **异步模式**：`spdlog::async_logger` + 线程池（队列满时阻塞写入线程，不丢日志）；`async = false` 时为同步双 sink。
- **双 sink**：轮转文件 + stdout（`console = false` 可关，用于重定向/后台运行）。
- **初始化前缓冲**：配置加载先于 logger 就绪，其间的日志进缓冲（上限 100 条），init 成功后回放；init 失败则整体降级为丢弃（main 在 stderr 提示一次，不影响服务可用性）。
- **格式**：`[YYYY-MM-DD HH:MM:SS.mmm][level] message`（与旧格式对齐，`graceful shutdown complete (signal=N)` 巡检标志保持不变）。

## 3. 前端实现要点（web/index.html）

- 无任何第三方资源：无 CDN、无框架、无构建，仅 HTML5 + CSS3（自定义属性）+ ES5/ES6 原生 JS（`fetch`、`DOMContentLoaded`、DOM 操作）。
- 工业风格：深灰蓝低眩光配色（`--bg:#1e2530`）、青绿强调色（`#2ea88a`）、状态色语义化（正常绿/告警黄/错误红）；`Segoe UI/Microsoft YaHei` 正文 + `Consolas` 等宽地址列；控件最小高度 36px 适配触摸。
- 功能：健康状态 5s 轮询；文件列表/新建文件（前端校验 `[A-Za-z0-9_-]{1,64}`）；点表表格渲染；行点击回填表单 → 单写更新；表单空 → 单写追加；错误经统一错误体渲染到底部状态栏。
