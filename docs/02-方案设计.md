# 02 方案设计 — 工业点位采集编辑工具 HTTP 服务

## 1. 第三方库选用范围与依据

均选自 `C:\github\cpp_works\third_party` 现有开源库，全部为**单头文件库**，无编译依赖、无网络安装需求，符合工业现场离线交付要求。

| 库 | 版本 | 文件 | 用途 | 选用依据 |
| --- | --- | --- | --- | --- |
| cpp-httplib | 0.66.0 | `third_party/cpp-httplib/httplib.h` | HTTP 服务、路由、静态页面挂载、**pre-routing 中间件钩子**（白名单拦截点） | 工业级单头 HTTP 库，自带线程池；`set_pre_routing_handler` + `req.remote_addr` 恰好提供中间件拦截能力，无需改动库源码 |
| nlohmann/json | 3.12.0 | `third_party/nlohmann/json.hpp` | 请求/响应 JSON 序列化、配置解析 | 事实标准 C++ JSON 库，API 安全（异常显式），避免手写解析引入缓冲区漏洞 |
| rapidcsv | 9.09 | `third_party/rapidcsv/rapidcsv.h` | CSV 读写 | 正确处理带引号/含逗号字段（RFC 4180），比手写 CSV 解析健壮；支持 UTF-8 BOM 读取 |
| spdlog | 1.17.0 | `third_party/spdlog/include`+`src`（编译库形态，bundled fmt 随附） | 分级/异步/轮转日志 | 2026-11-15 人工确认纳入白名单：异步+按大小轮转（10M×100）能力开箱即用，替代原自研轻量日志（docs/03 §2.1），规避自研异步日志的正确性风险 |

**不引入**：数据库（点表规模小且必须与组态软件以 CSV 交互）、任何 Web 前端库（需求明确禁用）。原"日志框架自实现"条款随 2026-11-15 日志系统升级（spdlog）作废。

## 2. 总体架构

```
浏览器（web/index.html，原生技术）
        │ HTTP :8080
        ▼
cpp-httplib Server（线程池）
        │
        ├─ ① 白名单中间件  set_pre_routing_handler（IP / Origin 匹配，未命中 403 短路）
        ├─ ② 统一错误/响应层（json 包络 + 错误码）
        ├─ ③ 业务路由 /api/v1/*
        │        │
        │        ▼
        │   PointStore（services/csv_store/include/csv_store/csv_store.h）
        │     · 文件表: <file> → shared_mutex
        │     · 读: shared_lock 加载 → 快照返回
        │     · 写: unique_lock → 内存修改 → 临时文件 + rename 原子替换
        └─ ④ 静态资源 mount："/" → web/ 目录
```

分层：`main.cpp`（装配）→ `api.cpp`（路由/参数校验/响应包络）→ `csv_store.h`（存储域）→ `whitelist.h`（访问控制域）。各层单向依赖，接口层不直接碰文件系统。

## 3. 接口设计（REST，前缀 `/api/v1`）

### 3.0 统一约定

- 请求体与响应体均为 `application/json; charset=utf-8`（静态页面除外）。
- **缓存控制**：所有响应（含静态页面）携带 `Cache-Control: no-store`，禁止浏览器/代理缓存 API 数据与页面，防止使用陈旧点表数据；前端对 GET 请求另追加 `_ts` 时间戳参数作双保险（服务端忽略该参数）。
- **成功响应**：HTTP 200，`{"code":0, "message":"ok", "data":<对象或数组>}`。
- **失败响应**：非 200 状态码，`{"code":<业务码>, "message":<摘要>, "details":<可选>}`。
- 业务错误码 = `HTTP状态码 * 100 + 序号`：

| HTTP | 业务码 | 场景 |
| --- | --- | --- |
| 200 | 0 | 成功 |
| 400 | 40001 | JSON 解析失败 |
| 400 | 40002 | 参数缺失/非法（文件名、字段值、枚举越界等） |
| 403 | 40301 | 白名单拦截 |
| 404 | 40401 | CSV 文件不存在 |
| 404 | 40402 | 点位行不存在（index 越界） |
| 405 | 40501 | HTTP 方法不允许 |
| 409 | 40901 | 文件已存在 / 点位名称在该文件中重复 |
| 500 | 50001 | 服务器内部错误（落盘失败等） |

### 3.1 列出 CSV 文件

```
GET /api/v1/files
```
成功 `data`：
```json
{ "files": [ { "name": "line1.csv", "rows": 12 } ], "data_dir": "data" }
```

### 3.2 新建 CSV 文件

```
POST /api/v1/files
{ "name": "line2" }              // 不含扩展名；合法字符 [A-Za-z0-9_-]，1~64 位
```
- 成功 `200`：`data: {"name":"line2.csv","created":true}`；文件已存在返回 `409/40901`。
- 副作用：写入仅含标准 6 列表头的新文件。

### 3.3 单读（Single Read）

```
GET /api/v1/points?file=line1&index=3
```
- 参数：`file` 必填；`index` 必填，0 基行号。
- 成功 `data`：`{ "index": 3, "point": { "name":"temp1", "io_address":"40001", "address_type":"io", "point_type":"float", "rw":"rw", "desc":"1#炉温" } }`
- 失败：`404/40401` 文件不存在；`400/40002` 参数非法；`404/40402` index 越界。

### 3.4 批量读（Batch Read）

```
GET /api/v1/points?file=line1&start=0&count=100
```
- 参数：`file` 必填；`start` 默认 0；`count` 默认 0 表示到文件尾；上限 10000。
- 成功 `data`：`{ "total": 150, "start": 0, "count": 100, "points": [ { "index":0, "point":{...} }, ... ] }`

### 3.5 单写（Single Write）

```
POST /api/v1/points
{
  "file": "line1",
  "index": 3,                    // 可选：有 → 修改该行；无 → 追加到表尾
  "point": {
    "name": "temp1", "io_address": "40001", "address_type": "io",
    "point_type": "float", "rw": "rw", "desc": "1#炉温"
  }
}
```
- 成功 `200`：`data: {"file":"line1.csv","index":3,"op":"update"|"append"}`
- 失败：`404/40401`、`400/40002`（字段缺失/枚举非法/index 越界）、`409/40901`（name 与其他行重复）、`500/50001`。

### 3.6 批量写（Batch Write）

```
POST /api/v1/points/batch
{
  "file": "line1",
  "items": [
    { "index": 0, "point": { ... } },      // 修改
    { "point": { ... } }                   // 追加
  ]
}
```
- 语义：**一个文件、一次加锁，整批在一个事务内处理**；逐条按单写校验。
- 成功 `200`：`data: { "applied": 2, "results": [ {"index":0,"op":"update","code":0}, {"index":150,"op":"append","code":0} ] }`
- 失败：任一条目校验失败则**整批拒绝**（全不生效），返回 `400/40002`，`details` 为 `{"item":<下标>,"message":<原因>}` 数组，保证批量操作原子性且可定位。

### 3.7 健康检查

`GET /api/health` → `200 {"code":0,"message":"ok","data":{"version":"1.0.0"}}`（同样受白名单保护）。

## 4. 白名单中间件设计

### 4.1 匹配维度与规则

配置文件 `config/whitelist.conf`，一行一条规则，`#` 开头为注释：

| 规则格式 | 维度 | 匹配规则 |
| --- | --- | --- |
| `192.168.1.10` | 来源 IP（IPv4/IPv6 精确） | 与 `req.remote_addr` 全等比较（IPv6 大小写不敏感） |
| `10.0.0.0/8` | 来源 IP（CIDR 网段） | IPv4 网段掩码匹配；`/0` 匹配全部 IPv4 |
| `origin:http://localhost:*` | 来源 Origin | 跨域请求 `Origin` 头按前缀通配匹配（`*` 仅可出现在末尾端口位置） |
| `origin:https://plant.example.com` | 来源 Origin | 前缀精确匹配 |

判定：**IP 命中任一 IP 规则，或 Origin 命中任一 origin 规则 → 放行**；两者皆未命中 → 拦截。

- 缺省行为：配置文件存在 → 白名单生效（仅放行所列来源）；**文件不存在 → 放行所有来源并打印 WARN 日志**，便于首次启动；出厂 `config/whitelist.conf` 内置 `127.0.0.1`、`::1`、`192.168.0.0/16`。
- 本服务默认直连场景，取 `remote_addr`（TCP 层地址，不可伪造）；不解析 `X-Forwarded-For`（避免伪造绕过）。

### 4.2 拦截行为

挂接 `httplib::Server::set_pre_routing_handler`（进入路由表之前执行）：

1. 提取 `req.remote_addr` 与可选 `Origin` 头；
2. 未命中 → 构造响应返回 `httplib::HandlerResponse::Handled` 短路：状态 `403`，JSON 体
   `{"code":40301,"message":"access denied by whitelist","details":{"ip":"<实际IP>","origin":"<Origin或空>"}}`；
3. 命中 → 返回 `HandlerResponse::Unhandled` 继续正常路由；
4. 每次拦截记录 WARN 日志（时间、IP、方法、路径），便于审计。

## 5. CSV 存储设计

### 5.1 存储路径与命名

- 数据目录：默认 `<工作目录>/data`，启动参数 `--data-dir` 可覆盖；目录自动创建。
- 文件名：`<名称>.csv`，名称限 `[A-Za-z0-9_-]{1,64}`（API 与前端双重校验；服务端对路径拼接做白名单字符过滤，杜绝 `../` 目录穿越）。
- 文件编码：UTF-8 带 BOM（`EF BB BF`），Excel 双击打开不乱码；首行标准表头：
  `name,io_address,address_type,point_type,rw,desc`

### 5.2 并发写入处理

1. **锁粒度**：`PointStore` 维护 `file → std::shared_mutex` 映射（映射表由独立互斥量保护）。读接口 `shared_lock`（可并发读），写接口 `unique_lock`（读写、写写互斥）。
2. **原子落盘**：写流程 = 加唯一锁 → 内存修改行集 → 写临时文件 `<file>.csv.tmp` → `std::filesystem::rename` 原子替换。任一步失败删除临时文件并返回 500，旧文件保持完好。
3. **无读缓存、以文件为准**：每次调用从磁盘加载（点表 ≤10 万行，本地盘毫秒级）；外部用 Excel 手改文件后无需重启即可读到最新内容。
4. **批量写事务**：单锁整批处理，内存中全部校验通过后才落盘一次（见 3.6）。

## 6. 错误处理与日志

- 统一错误码表（见 3.0）；所有 handler 包裹 try/catch，未知异常 → `500/50001`，不向客户端泄漏堆栈。
- 日志：轻量分级（INFO/WARN/ERROR）输出到控制台，格式 `[HH:mm:ss.mmm][LEVEL] message`。

## 7. 前端页面设计（原生 Web 技术）

- 单文件 `web/index.html`（内联 CSS/JS，无任何第三方资源、无构建步骤），由 cpp-httplib 挂载在 `/`。
- 布局：顶栏（标题 + 服务器状态）｜左侧栏（文件列表 + 新建文件表单）｜主区（点表表格 + 编辑表单）｜底部状态栏（最近操作结果）。
- 工业配色：深灰蓝底（#1e2530 系）低眩光、青绿强调色（#2ea88a）、状态色（成功绿/告警黄/错误红）；字体：`"Segoe UI", "Microsoft YaHei"` 正文 + `Consolas` 等宽用于地址列；最小命中区域 ≥ 36px，适配触摸屏。
- 交互：轮询 `GET /api/health` 显示在线状态；文件切换/新建后调批量读渲染表格；添加表单调单写（追加）；行选中回填表单调单写（更新）；全部错误用统一错误体渲染到状态栏。

## 9. 应用配置文件（app.toml，toml++ 解析）

启动配置三级优先级：**命令行参数 > `app.toml` > 内置默认值**。

| 键 | 类型 | 内置默认 | 说明 |
| --- | --- | --- | --- |
| port | int | 8080 | HTTP 监听端口 |
| data_dir | string | "data" | CSV 数据目录 |
| web_dir | string | "web" | 前端资源目录 |

- `config_dir` 不可经 app.toml 设置（引导依赖：定位 app.toml 本身），仅命令行 `--config-dir`。
- 文件缺失或键缺省 → 使用默认值（零配置可启动）；文件格式非法 → 记 WARN 后忽略整文件；键类型非法 → 记 WARN 后忽略该键。
- 解析库：toml++ v3.4.0（硬性约束 13，不得替换）；命令行解析库：cxxopts v2.2.0（同约束），支持 `--port=8080` 与 `--port 8080` 两种写法及 `--help`。
- 实现：`common/app_config.h`（AppOptions + load_app_config）、`common/app_config.cpp`；未知命令行参数记 WARN 忽略。

## 10. 构建与运行

- 编译器要求：支持 C++17 的 MSVC 或 MinGW-w64 GCC≥8（GCC 8 需链接 `-lstdc++fs`）。
- CMake：`cmake -B build -G "MinGW Makefiles" && cmake --build build`
- 运行：`tagledger.exe --port=8080 --data-dir=data --web-dir=web --config-dir=config`
