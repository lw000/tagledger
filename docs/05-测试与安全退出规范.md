# 05 测试与安全退出规范

本规范对单元测试、性能压测与集成测试具有强制约束力；修改测试或退出相关代码前必须先阅读本文件。

## 1. 测试框架：Catch2（third_party 现有库）

- **唯一框架**：单元测试与性能压测一律使用 `C:\github\cpp_works\third_party\catch2`（Catch2 **v3.16**，编译库形态，该目录即 `src/catch2` 的内容）。
- **头文件引用**：`#include <catch2/catch_test_macros.hpp>`、`#include <catch2/benchmark/catch_benchmark.hpp>` 等；包含根为 `third_party`（`-I third_party`）。
- **库的构建**：`third_party/catch2` 不含 CMakeLists，由本项目 CMake 以 `file(GLOB_RECURSE)` 收集全部 `*.cpp` 编译为静态库 `catch2_lib`，并 `PUBLIC` 传播两个包含目录：`third_party/` 与 `build/generated/`。后者中的 `catch_user_config.hpp` 由 `catch_user_config.hpp.in` 经 CMake `configure_file` 生成——它不是源码树的一部分，**缺失即编译失败**，不要手工创建或提交。
- **main()**：v3 编译库自带 `internal/catch_main.cpp`；测试目标**禁止**再定义 `CATCH_CONFIG_MAIN` 或自写 `main`。
- **GCC 8.1 注意**：Catch2 断言中 `a == b && c` 会触发 "chained comparisons" 静态断言，组合断言必须整体加括号 `REQUIRE((a == b && c))`。

## 2. 测试目录结构、命名与分组

```
tests/
├─ unit/                     单元测试（纯逻辑，无网络/子进程）
│  ├─ test_whitelist.cpp     白名单匹配        [unit][whitelist]
│  ├─ test_csv_store.cpp     点位存储域        [unit][store]
│  ├─ test_shutdown.cpp      安全退出控制器    [unit][shutdown]
│  └─ test_app_config.cpp    应用配置加载      [unit][app_config]
├─ perf/                     性能基准（Catch2 BENCHMARK）
│  └─ test_perf.cpp          [perf][store] / [perf][whitelist]
└─ scripts/                  集成与编排脚本（Python，仅标准库）
   ├─ run_tests.py           统一测试入口（编排以下全部步骤）
   ├─ smoke_api.py           API 冒烟（复用运行中的服务，--base-url）
   ├─ concurrency_test.py    并发写一致性（--base-url）
   └─ graceful_shutdown_test.py  安全退出集成（自管服务生命周期）
```

| 项 | 规则 | 示例 |
| --- | --- | --- |
| TEST_CASE 名 | `<模块>/<被测行为>`，英文 | `whitelist/cidr match` |
| 分组标签 | 首标签必为 `[unit]`/`[perf]`/`[shutdown]`，后跟模块标签 | `[unit][store]` |
| SECTION | 子场景用 SECTION，不另开 TEST_CASE | 枚举字段校验分支 |
| 文件名 | `test_<模块>.cpp`，一模块一文件 | `test_shutdown.cpp` |
| BENCHMARK 名 | `perf/<对象>/<操作>` | `perf/store/batch read` |

- 运行方式：按标签过滤 `tagledger_tests "[unit]" / "[shutdown]" / "[perf]"`；CTest 注册名 `tagledger_unit/tagledger_shutdown/tagledger_perf`；一键全跑：`python tests/scripts/run_tests.py`。
- 单元测试禁止：启动真实服务、绑定固定端口、依赖执行顺序、共享可变全局状态；每个用例自建 `build_test_data/<模块>` 临时目录并清理。
- 性能基准只放 `tests/perf/`，数据规模用命名常量（如 `kRows = 1000`）。

## 3. Python 测试脚本规范

1. 仅用标准库（`urllib/json/subprocess/threading/tempfile/argparse`），禁止 pip 依赖——保证工业现场离线可运行。
2. 跨平台：路径用 `os.path` 拼接，禁止硬编码 `\` 与盘符；服务以 `subprocess.Popen` 启动并在 `finally` 中确保回收子进程与临时目录。
3. 编码：含中文的脚本保存为 UTF-8 并带 `# -*- coding: utf-8 -*-`；**控制台输出用 ASCII**（兼容 GBK 终端）。
4. 退出码即结果：全过 0，任何失败非 0；`run_tests.py` 汇总各步骤。
5. 依赖运行中服务的脚本接受 `--base-url`；自管生命周期的脚本不接受该参数（由 `run_tests.py` 区分传参）。

## 4. 跨平台路径处理与构建配置

| 平台 | 要点 |
| --- | --- |
| Windows（MinGW/MSVC） | `-D_WIN32_WINNT=0x0A00 -DNOMINMAX -DWIN32_LEAN_AND_MEAN`；链接 `ws2_32`；文件操作走 `util.h`（`GetFileAttributesA/_findfirst`）；原 **禁用 `std::filesystem`** 条款随 2026-11-15 工具链升级（GCC 16.2）解除，正在逐步迁移（见 docs/03 §2.1） |
| Linux/macOS | `find_package(Threads)` 链 pthread；`util.cpp` 走 `opendir/stat` 分支；可从外部发送 SIGTERM |
| 公共 | C++17；路径分隔符统一 `/`（`util::path_join` 输出），两个平台均接受；CMake 4.5.0 支持 `cmake -B` 直接配置 |

## 5. 优雅安全退出机制

实现：`common/shutdown.h` + `common/shutdown.cpp`（`ShutdownController`），集成于 `apps/tagledger/main.cpp` 与 `POST /api/admin/shutdown`。

### 5.1 信号捕获时机

信号处理器在**全部组件（白名单/存储/路由）构造完成之后、开始监听之前**安装（`main.cpp` 阶段 2）。过早安装会在半初始化状态上执行退出流程；过晚则监听期存在无保护窗口。捕获 `SIGINT`、`SIGTERM`（Windows 另含 `SIGBREAK`）；`SIGKILL/SIGSTOP` 不可捕获——强杀下的数据安全由存储层"临时文件 + 原子替换"兜底。

### 5.2 信号处理器约束

处理器内**只写两个变量**：`volatile std::sig_atomic_t` 与无锁 `std::atomic<bool>`；不做 I/O、堆分配与锁操作。真正的退出动作由 `install_handlers()` 启动的 monitor 线程（100ms 轮询标志）与请求方线程（管理端点路径）执行。信号→退出动作延迟上限约 100ms。

### 5.3 资源释放顺序（main.cpp 阶段 5，固定不可调整）

1. **停止接入**：`svr.stop()`——关闭监听 socket、置 shutdown 标志、不再排队新任务；
2. **等待在途任务收尾**：`listen_thread.join()`——httplib `ThreadPool::shutdown()` join 全部工作线程并排空任务队列（worker 退出条件为 `shutdown_ && jobs_.empty()`），即**已接受与已排队的请求全部执行完毕后**才返回；在途的 CSV 写由"加载-修改-整文件临时写入-rename 原子替换"保证要么完整落盘要么保持旧文件；
3. **存储域析构**：`PointStore` 无后台线程/缓存，栈序自动析构；无 .tmp 残留（原子替换已完成或失败即删除）；
4. **日志 flush**：`shutdown_logger()`（spdlog flush 落盘 + 异步线程池排空），置于退出顺序**最后一步**；最后一条 `graceful shutdown complete (signal=N)` 可作为巡检标志。日志格式 `[YYYY-MM-DD HH:MM:SS.mmm][level] message`（文件 + stdout 双 sink；等级/异步队列/轮转策略来自 app.toml `[log]` 段）。

退出触发路径有三条且幂等汇合于 `request_stop()`：SIGINT/SIGTERM/SIGBREAK → monitor 线程；`POST /api/admin/shutdown`（白名单保护）→ 请求线程；测试代码直接调用。
