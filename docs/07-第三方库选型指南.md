# 第三方库选型指南（docs/07）

> **文档定位**：third_party 全部 36 个条目（白名单七库 + 备用库 29 项）的选型参考手册——为每个库明确"核心功能、典型使用场景、适用业务类型、选型判断依据"，供 AI 与开发者快速检索比对"何种业务需求下应选用哪个库"。
> **权威关系**：库的依赖白名单、禁改规则与版本登记以 `docs/06-技术架构文档.md` 附录 A 与 `third_party/README.md` 为权威；本文件是选型决策辅助，不改变任何登记条款。
> **快速用法**：先查第 2 节"场景快速检索表"定位候选库 → 再读该库详情卡（第 4/5 节）确认适用性与前置条件 → 备用库还须核对第 3 节启用门槛与第 6 节许可证合规。

## 1. 选型总原则（L 系列摘要）

1. **白名单优先**：需求可由白名单七库覆盖时，禁止引入白名单外实现（L1/L2）；参数解析、配置解析、日志等有强制库，不得自研等价轮子。
2. **启用备用库 = 登记前置**：备用库仅作检索备料，任何 include/CMake 引用前必须走 F5/Q6 流程——更新 docs/06 白名单 + 写明选型依据 + 人工确认，并同步 third_party/README.md。
3. **不修改库源码（F5）**：项目侧适配一律写在项目代码中；升级 = 整体替换目录。
4. **许可证合规**：见第 6 节；vendored 副本内无许可声明的库（boolinq、glob、croncpp.h、thread_pool_dp）启用前必须先补齐上游 LICENSE 文件（经 F5/Q6）。
5. **版本以实测为准**：所有版本号以库内版本宏/头注释核对为准（方法见 third_party/README.md 第 8 节）。

## 3. 备用库启用门槛（操作清单）

1. 走 F5/Q6：写选型依据（对比候选、许可证、维护状态）→ 更新 docs/06 附录 A 白名单 → 人工确认。
2. 许可证合规核对本指南第 6 节；无许可声明的 4 项（boolinq、glob、croncpp.h、thread_pool_dp）先补上游 LICENSE。
3. 同步 third_party/README.md（第 2 节白名单表 + 第 6 节状态）与本指南状态列。
4. 职责重叠库不并存：测试只留 Catch2 或 doctest 之一；JSON 主链路只留 nlohmann（json_struct 仅可作强类型映射补充）；线程池/无锁队列按场景二选一；filesystem 兼容层在 C++17 下禁用。

### 4.1 cpp-httplib — HTTP 服务/客户端

| 项 | 内容 |
| --- | --- |
| 目录/版本 | `third_party/cpp-httplib/`，0.66.0（`CPPHTTPLIB_VERSION`） |
| 形态/许可 | 单头（httplib.h）/ MIT |
| 核心功能 | HTTP/1.1 服务端与客户端；线程池并发；路由分发；中间件挂接点 `set_pre_routing_handler`；error_handler 兜底；multipart、Range、keep-alive；静态文件托管 |
| 典型使用场景 | 设备/服务内嵌 Web 管理 API（REST + 统一包络）；本地 Web UI 托管；对内 HTTP 客户端调用 |
| 适用业务类型 | 中小并发（数十~数百连接）的现场级/单机服务：工业点表服务、网关管理端点、健康检查端点 |
| 不适用 | 高并发大流量（万级 QPS 网关）、HTTP/2/QUIC、反向代理场景 |
| 选型判断依据 | 需要"进程内自带 HTTP 服务、零外部依赖、单头可审计"时选它；需要强中间件生态或异步 IO 模型时不选 |
| 项目内用法 | `services/http_server/`：白名单中间件 → 路由 → 统一包络 → 静态页；业务码 40301/40401 等（docs/02） |
| 注意事项 | 须 `_WIN32_WINNT=0x0A00`；0.66 的 error_handler 对所有 ≥400 回调，业务已写错误体（res.body 非空）必须跳过 |
